# 解题经验

## 算法选择

### 正则表达式

**核心原则：只有"固定格式"和"简单的可选字符"这两种情况才用正则表达式。**

固定格式之间也有量级差异，从简单到复杂大致分三档：

**场景 1：固定长度与字符类型**

比如：工号必须是 8 位纯数字。

```js
/^\d{8}$/
```

**场景 2：固定前缀 + 固定格式**

比如：工号必须是 2 个大写字母开头，后面跟 6 位数字（如 AB123456）。

```js
/^[A-Z]{2}\d{6}$/
```

**场景 3：简单的可选字符**

比如：工号可以是纯数字，也可以带一个字母前缀。

```js
/^[A-Za-z]?\d{7}$/
```

可以看到，即使场景 3 也只是把"固定"放宽为"可选一个字符"，量词和分支都保持在直接可数的范围内。

**但凡涉及动态/条件格式校验——这是正则的深水区——就不应该用正则。**

比如：一个英文字母 + 任意个 0 + 特征数字字段 + 任意个 0。

这类格式的致命问题在于**组成部分之间没有确定的边界**：0 既是两端的"填充物"，又可能天然出现在特征数字字段里。正则 `/^[A-Za-z]0*(\d+)0*$/` 看似能匹配，但对 `A0051200` 来说，`(\d+)` 到底应该捕获 `5`、`512` 还是 `51200`？填充 0 和特征数字的边界无法从格式本身判断，写出来的正则要么误匹配，要么捕获结果不可信。

此时正确的做法是放弃正则，用普通代码分步解析（先取首字母，再明确约定两端 0 的剥离规则），或者推动上游把格式改造得有确定的分隔方式。判断标准很简单：**当你需要用"条件"去解释格式的含义时，问题已经超出正则的能力边界了。**

## 解题技巧

### 1. 获取循环偏移位置

**场景**：位置沿着一个固定长度的序列循环移动，越界后从头接着数。比如大写字母 `Y` 往后偏移 2 位：`Y → Z`，再往后没有字母了，就回到开头继续数，结果就是 `A`。凯撒密码、循环队列、轮播图下标计算都属于这类问题。

**核心技巧**：把位置抽象为 `0 ~ n-1` 的下标，用**取模运算**实现越界回绕。

```typescript
// 大写字母循环偏移：offset 为往后偏移的位数
function shiftChar(ch: string, offset: number): string {
    const base = 'A'.charCodeAt(0);

    // 1. 字母转下标：A -> 0，Y -> 24，Z -> 25
    const index = ch.charCodeAt(0) - base;

    // 2. 加偏移后取模，越界部分自动从头开始：Y 偏移 2 -> (24 + 2) % 26 = 0 -> A
    return String.fromCharCode(base + (index + offset) % 26);
}
```

取模是关键：`Y` 的下标是 24，偏移 2 位后是 26，`26 % 26 = 0`，正好回到 `A`。

**注意**：如果偏移量可能是负数（往前偏移），取模结果可能为负，需要再补一圈取模：

```typescript
const next = ((index + offset) % n + n) % n;
```
