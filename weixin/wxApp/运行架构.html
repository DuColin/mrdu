运行架构：双线程架构 ​

微信小程序的双线程架构是实现“接近原生体验”和“安全管控”的基础。同时也是小程序开发框架设计的基础。

传统 web 架构 ​

浏览器内部是多线程，但对前端开发者来说，最关键的两条线程是死对头。 GUI 渲染线程 与 JS 引擎线程 互斥，绝对不能同时运行

传统 web 架构的缺点：

  1. JS 会阻塞渲染，直接导致卡顿、白屏、假死（最核心缺陷）

因为渲染和 JS 互斥：

  • JS 有大量计算、死循环、长任务 → 渲染线程被卡住
  • 页面卡住不动、点击无响应、滚动卡顿
  • 首屏 JS 太大 → 白屏时间极长

比如

js
// 简单的长任务
while(true) {}

页面直接卡死，渲染完全停止。

  1. DOM 操作 = 性能黑洞，频繁操作必卡顿 DOM 是跨线程对象，操作 DOM 本质是：JS 线程 → 通知渲染线程 → 构建 DOM → 触发重排 / 重绘

    • 每操作一次 DOM，就可能触发一次页面重新布局
    • 每操作一次 DOM，就可能触发一次页面重新布局
    • Vue/React 用虚拟 DOM 做优化，也只是 “缓解”，没根治

  2. 无安全隔离，恶意代码无法管控

    • JS 能直接操作 window / document，可随意跳转外链、获取 Cookie、监听用户输入
    • XSS 攻击可轻易注入恶意脚本
    • 无法限制能力，不适合微信这种超级 App 内嵌第三方应用的场景

  3. 渲染行为不可控，体验参差不齐

    • 不同浏览器内核（WebKit/Gecko）渲染差异大
    • 响应式设计复杂，需要针对不同设备尺寸编写多套CSS样式，开发和维护成本高。
    • 移动端浏览器内存、WebView 质量不一
    • 页面卡顿、白屏、崩溃无统一兜底
    • 无法保证所有小程序体验一致

  4. 资源加载串行，首屏速度慢

    • HTML 解析遇到 <script> 会停止渲染，先下载执行 JS
    • 资源加载、解析、渲染串行执行
    • 首屏加载速度天然慢

  5. 无法做生态管控，不适合平台级应用 浏览器是开放环境，无法限制：

    • 不能禁止跳转外链
    • 不能限制文件体积
    • 不能管控权限（定位、相机、支付）
    • 无法做统一审核、更新、下架

双线程架构 ​

微信小程序：针对传统 Web 缺陷，双线程架构的设计目的

  1. 彻底解决 “JS 阻塞渲染” 传统 Web：渲染和 JS 互斥，一个卡全都卡

小程序设计：

  • 渲染层（WebView）：只做渲染，不跑业务 JS
  • 逻辑层（独立 JS 引擎）：只跑业务，不参与渲染

两个线程并行运行，互不阻塞

效果：

  • 逻辑层做复杂计算、网络请求 → 渲染层依然流畅滑动、渲染
  • 从根源消灭 “JS 卡死页面” 的问题
  1. 用“数据驱动”替代“DOM 操作”

传统 Web：手动操作 DOM → 频繁重排重绘

小程序设计：

  • 禁止逻辑层直接访问 DOM、无window/document
  • 只能通过 setData 传递数据到渲染层
  • 渲染层内部做 diff 更新，批量渲染

效果：

  • 开发者无法直接操作 DOM，从语法层面杜绝性能黑洞
  • 统一渲染更新机制，避免滥用 DOM 导致卡顿
  1. 双线程隔离 + Native 桥 —— 构建安全沙箱，满足微信管控 传统 Web：JS 权限过大，无法管控

小程序设计：

  • 渲染层不能执行业务 JS，逻辑层不能操作 UI
  • 所有通信必须经过微信 Native 层转发
  • 所有能力（相机、定位、支付）必须通过 wx.xxxAPI，由微信授权

效果：

  • 彻底杜绝 XSS、恶意跳转、权限窃取
  • 微信可监控、拦截、审核所有小程序行为
  • 实现平台级安全管控
  1. 多 WebView 并行 + 预加载 —— 解决首屏与切换体验 传统 Web：单 WebView，切换页面重新加载渲染

小程序设计：

  • 每个页面一个独立 WebView（渲染层）
  • 页面栈管理，可预创建、复用 WebView
  • 双线程并行加载资源（逻辑层加载 JS，渲染层加载 WXML/WXSS） 效果：
  • 页面切换无白屏、更接近原生 App 体验
  • 首屏并行加载，速度大幅提升
  1. 统一渲染规范 —— 保证全设备体验一致

传统 Web：不同手机 / WebView 渲染差异大小程序设计：

小程序设计：

  • 统一 WXML/WXSS 语法，禁用危险 CSS 选择器
  • 统一 rpx 自适应单位，抹平设备差异
  • 底层由微信统一适配 iOS/Android 效果：
  • 所有小程序在不同设备上表现一致
  • 降低开发适配成本，提升用户体验
  1. 严格生态约束 —— 适配微信小程序平台定位

传统 Web：完全开放，无法约束

小程序设计：

  • 包体积限制（主包 2M）
  • 域名白名单
  • 页面栈限制
  • 审核机制、权限管控

效果：

  • 保证小程序轻量、快速、稳定
  • 适合微信 “即用即走” 的产品定位
